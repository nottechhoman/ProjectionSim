# v4 — mappings + timeline playback

## Content model

Content lives only on **layers**. Each layer picks one **mapping**; a mapping says
how its canvas lands on a set of screens.

| Mapping | Canvas → screen |
|---|---|
| Direct | the screen's own UV layout (fit: stretch / fit / crop / pixel) |
| Perspective | projected from a viewpoint — free camera, or locked to a projector (optionally *projector only*: just that projector shows it, like v1–v3 "raw") |
| Parallel | orthographic along a frame's −Z |
| Feed | per-screen region of the canvas (surface UV: mesh / planar / cylindrical / spherical, flip, rotate, repeat, wrap) |
| Cylindrical / Spherical | azimuth (+ height / elevation) around a centre |

Each frame every screen bakes **one texture**: its live layers composited bottom to
top (normal / add / multiply), each sampled through its mapping
(`src/mapping/ScreenTextureBaker.ts`, `shaders/bake.frag.glsl`, CPU mirror
`src/mapping/sample.ts`). Each projector renders the textured screens from its own
camera into a **content feed**; the viewport, output previews and output windows
sample that feed through the corner-pin warp and blend mask.

New screens get a Direct mapping named after them; new projectors get a
Perspective mapping locked to them. v1–v3 files migrate on load
(`src/mapping/migrate.ts`); `src/mapping/migrationRender.test.ts` checks every bundled
sample renders the same colours as before.

## Playback

`Show { fps, mappings, tracks, activeTrackId }`, `Track { durationSec, layers, sections, cues }`.
Layers carry timing: start, duration, in / out, play mode (loop / once / hold last /
ping-pong), speed, fades, volume, mute.

* **Master clock** (`src/playback/clock.ts`): `playhead = anchor + (now − anchorWall) × rate`.
* **evaluate(track, t)** (`src/playback/evaluate.ts`): live layers, opacity after
  fades, media time.
* **Media sync** (`src/playback/mediaSync.ts`, maths in `syncMath.ts`): one player per
  video layer; audio on by default.

### Sync policy (measured in Chrome on an M1 Max, 8 × 1080p30 H.264 with audio)

Findings that shaped it:

1. Chrome decodes 8 × 1080p30 in real time easily (0 skipped frames when left alone).
2. Each `<video>` shows its frames a steady ~40–110 ms behind its own clock — the same
   for clips started together.
3. Any `playbackRate ≠ 1` makes Chrome skip frames (≈ 4/s at +1 %).
4. A seek on long-GOP footage decodes from the last keyframe: 0.2–0.8 s here.

So:

* drift is measured from the frame actually on screen (`requestVideoFrameCallback`:
  its media time vs the clock at its display time), against a slowly learned common
  latency — a shared offset is not "corrected";
* the rate is nudged (≤ ±5 %) only beyond 1.5 frames, until back within 0.5 (hysteresis);
* seek when more than 2 frames off **and** more than twice that video's measured
  seek cost; seeks land ahead by that cost;
* play pre-rolls the clock by the measured start-up latency;
* looping layers get a second player started just before the wrap, which takes over
  at it (a seek at the wrap stalls);
* clips starting within 2 s are preloaded; videos pause and park on the exact frame
  when the transport pauses.

Result (`docs/screenshots/v4-m2-8x1080p.png`): 60 fps with no long frames, all 8
clips within ~1 frame of each other, no seeks during steady playback; a few skipped
frames around each loop wrap while the hand-off timing settles. Lower-resolution
proxies were not needed.

## UI

* Studio → **Mappings**: list (add / rename / duplicate / delete) and editor (screens,
  resolution, per-kind controls, feed region editor).
* **Layers** panel (More → Layers): stack with a mapping dropdown per row.
* **Inspector** shows the selected layer (media, mapping, placement, timing, audio).
* **Transport** (play / pause / stop, `HH:MM:SS:FF`, rate) on every device; the
  **timeline** (ruler + scrub, clip bars you drag / trim, fades, loop marks,
  playhead) on desktop, compact on tablet, hidden on phone.

## Show control (sections, cues, play modes)

* **Sections** (`Track.sections`): a time range with an end action —
  *continue* (play on), *stop* (stop and rewind to the section start),
  *hold* (stop on the last frame), *loop* (back to the start, keep playing).
* **Play modes** (transport dropdown): *Play* (end actions apply), *Play section*
  (stop at the current section's end), *Loop section* (loop it whatever its action).
* **Cues** (`Track.cues`): named times. **GO** plays from the cue you are parked on,
  otherwise jumps to the next cue and plays; the Cues panel shows what is on standby.
* Logic is pure and tested in `src/playback/showControl.ts`; commands in
  `src/playback/controls.ts`.

| Key | Action |
|---|---|
| Space | play / pause |
| Enter | GO |
| Esc | stop (back to 0) |
| ← / → | one frame back / forward (pauses) |
| Shift + ← / → | previous / next cue |
| L | toggle Loop section |
| M | add a cue at the playhead (measure mode moved to More → Tools) |

Screenshot: `docs/screenshots/v4-m3-cues.png`.

## Milestone 4: setlist, filtering, masks, model UVs

* **Setlist**: the transport, cues and timeline follow the active track. Add,
  duplicate, rename, reorder, delete and switch tracks from the timeline bar or the
  Cues panel. Switching stops the transport and goes back to 0. Everything is
  saved and undoable.
* **Mapping filtering** now changes the bake. *Nearest* snaps to the mapping
  canvas pixel grid and fetches media texels unfiltered. *Bilinear* is the default.
  *MSAA 2×* takes two rotated-grid sub-samples per screen texel.
* **Mapping mask**: pick an image (or import one) in the mapping editor. Its
  brightness over the mapping canvas multiplies every layer on that mapping
  (white shows, black hides).
* **Model UVs**: each screen's UV layout is checked for overlap and for UVs outside
  0–1. The Inspector and the mapping editor warn about it. For imported models,
  *Generate non-overlapping UVs* replaces the UVs with an atlas: triangles are
  grouped into flat islands by facing axis and shelf-packed into 0–1
  (`src/mapping/uvAtlas.ts`).

Screenshots: `docs/screenshots/v4-m4-mask-filter.png`, `docs/screenshots/v4-m4-mask-viewport.png`.

## Milestone 5: keyframes

* Each layer can animate **opacity, x, y, scale and rotation** with keyframes
  (`Layer.keyframes`). Times are in seconds from the layer's start. A key's ease
  (*linear* or *ease in/out*) shapes the segment that leads to the next key. Values
  hold before the first key and after the last.
* x / y / rotation replace the rect's value, scale grows the rect about its centre,
  and opacity replaces the layer opacity; fades still multiply on top. The pure
  `evaluate(track, t)` returns the animated `rect` and `opacity`, and the bake uses
  them (`src/playback/keyframes.ts`).
* **Timeline**: a coloured diamond per key on the layer row (white opacity, red x,
  green y, yellow scale, blue rotation). Drag one to move it (snaps to frames);
  click to select it; **Delete** removes the selected key.
* **Inspector → Keyframes**: shows each property's value at the playhead,
  ◇/◆ adds or removes a key there, and ◀ ▶ jump to the previous / next key. On a
  property that already has keys, typing a value keys it at the playhead. The
  selected key's time, value and ease can be edited directly.

Screenshot: `docs/screenshots/v4-m5-keyframes.png`.
